# OpenSpec in Marimay

OpenSpec records proposed changes, their design, and implementation tasks.
The language and toolchain contracts remain in [docs/spec](../docs/spec/),
with the authority order defined by [AGENTS.md](../AGENTS.md).

| Information | Existing source |
| --- | --- |
| Required behavior and requirement IDs | [Specifications](../docs/spec/) and [requirements](../docs/requirements.md) |
| Accepted rationale | [Design decisions](../docs/design/decisions.md) |
| Code and test ownership | [Compiler architecture](../docs/implementation/compiler-architecture.md) |
| Delivery and acceptance state | [Roadmap](../ROADMAP.md) and [checkpoint ledger](../docs/implementation/checkpoints.md) |
| Revision and platform evidence | [Evidence index](../docs/implementation/evidence/README.md) and [CI](../docs/ci.md) |
| Contribution and security rules | [Contributor guide](../CONTRIBUTING.md), [agent workflow](../docs/agent-workflow.md), and [security policy](../SECURITY.md) |

Keep active work under `changes/` and archived change records under
`changes/archive/`. A capability summary under `specs/` links the existing
normative documents. A proposal or summary cannot override an accepted contract.

For a semantic change, identify the existing requirement and decision, resolve
any conflicting contract, and update the normative documents with the code,
focused tests, VM/native comparisons, formatter fixtures, and public examples.
Use [config.yaml](config.yaml) and the installed OpenSpec workflows to keep
proposal, design, and task artifacts connected to those sources.

With the OpenSpec CLI installed, inspect planning state and validate artifacts:

```sh
openspec list --json
openspec list --specs --json
openspec validate --all --strict
```

The committed agent workflows were generated by OpenSpec 1.16.1. See the
[official installation instructions](https://github.com/Fission-AI/OpenSpec/blob/main/docs/installation.md)
for CLI setup. The bootstrap commands in [CONTRIBUTING.md](../CONTRIBUTING.md)
use CMake, C17, and Python directly; OpenSpec runs separately for change planning.

Record completed commands and exact platform scope in the change. Archive
planning records without treating them as milestone verification; roadmap
status follows the evidence rules in AGENTS.md.
