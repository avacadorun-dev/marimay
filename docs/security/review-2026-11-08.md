# Publication security review — 2026-11-08

Status: reviewed for the initial public source import. Fresh GitHub platform CI is still required; this is not a supported release.

This review covers publication privacy and selected compiler/runtime, build,
Python-tool, and CI trust boundaries. It is not a comprehensive independent
C vulnerability audit, a penetration test, or a proof of absence of data leaks.

## Findings and disposition

1. **High — historical privacy metadata.** Original commits and development
   evidence included private contact/infrastructure details. Publication uses
   a separately sanitized history; the original stays local. See
   [publication policy](publication.md).
2. **Medium — public automation supply chain.** Floating artifact action tags
   and an older private-CI-only optional JIT job needed migration. GitHub
   workflows pin actions to full commits, use read-only repository permissions,
   persist no checkout credential, use no repository secrets, and run on
   GitHub-hosted runners. The optional JIT fetch is explicit and pinned.
3. **Medium — developer evidence can contain sensitive data.** Native diagnostic
   collectors retain source/logs, provenance includes compiler paths, and
   benchmark tools can record process information. These outputs stay local
   unless deliberately shared; public CI uploads only selected outputs from a
   clean public checkout. They are not generic secret scrubbers.
4. **Informational — host tools are trusted.** Native C compiler/linker and
   Python/CMake tools execute outside language capabilities and can inherit
   host environment values. VM verification is not OS process isolation.
   Hostile workloads require an isolated environment.

## Secret and data-flow review

Gitleaks 8.30.1 was obtained from its official release and checked against the
published SHA-256. The original all-ref scan produced 1,735 matches: 1,730
file SHA-256 inventory entries, four occurrences of the C expression
`key.f64_bits`, and one ordinary prose phrase. Context-specific allowlists cover
these reviewed non-credentials, plus one exact truncated checksum fragment at
an archive scanner buffer boundary; arbitrary hexadecimal API keys remain scanned.
No confirmed credential was identified in that scan.

An additional offline scan inspected reachable Git objects, commit metadata,
working files, and compressed evidence for provider tokens, key material,
credential URLs, personal paths, emails, and internal endpoints. Privacy
findings were addressed in the public copy, not merely deleted at its tip.

Focused source inspection found no compiler/runtime telemetry, analytics,
automatic crash-upload, or update-check implementation. Default CMake builds
use local inputs; optional JIT CI explicitly fetches a pinned public dependency.
CI contacts GitHub and public toolchain/package providers and uploads selected
artifacts. This review does not cover unrelated host software, agent providers,
or arbitrary programs users choose to execute.

## Validation

Local platform: macOS ARM64, AppleClang, CMake, Python. Results:

| Check | Result |
| --- | --- |
| Original `main` history | All 246 original commits retain parent topology and author/committer dates after privacy rewriting |
| Implementation comparison | `bootstrap/`, `runtime/`, and `std/` trees are identical to the original committed `main` |
| Gitleaks 8.30.1, `git --log-opts="--all" --max-archive-depth=3` | No unsuppressed findings after reviewed, narrowly scoped false-positive rules |
| Offline publication guard, current tree and all reachable objects | No findings; gzip inputs are fully decompressed and PNG text/EXIF metadata is inspected |
| CMake Debug build | Passed with warnings treated as errors |
| Debug CTest | All 89 applicable cases passed across the full run and focused reruns |
| macOS ASan/UBSan | Frontend, bytecode, and runtime suites passed across the focused run and frontend rerun |
| Python tools | 18 tests passed across diagnostics, CLI acceptance, and publication privacy |
| Repository gates | Generated files, documentation links, spec terms, examples, syntax coverage, C memory policy, architecture, roadmap, and release contract passed |
| GitHub workflow syntax | actionlint 1.7.12 passed |

An initial parallel test attempt hit local disk pressure. The subsequent full
serial run found a documentation-asset installation failure; the install rules
were corrected and the distribution lifecycle test passed. Privacy editing also
required preserving the exact backslash intent of synthetic Windows formatter
fixtures; final frontend checks passed after CMake refreshed its fixture copies.
No compiler/runtime semantics were changed to resolve these checks.

The public copy includes MIT, Unicode attribution/license text, and a separate
Unicode package in its SPDX metadata. Final logo pixels are preserved in the
standalone source asset, with file metadata removed. The README uses a locally
stored banner and no remote image, font, badge, or tracking pixel.

Linux LeakSanitizer, Windows, other Tier 1 platforms, full sanitizer matrices,
optional JIT, sustained fuzzing, and Valgrind remain remote CI obligations.
Their workflows have been migrated; their configuration is not a passing
result. Platform and product gates remain open. No claim that all leaks or
vulnerabilities are absent is made.
