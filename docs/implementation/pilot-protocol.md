# E0 agent pilot protocol

Status: normative for the E0 gate under [D124](../design/decisions.md).
Entry: an alpha release closes the slot named in the E0 milestone.
Owner: the E0 card in that milestone; evidence lands in `evidence/`.

## 1. What the pilot is for

The pilot answers one question: **can a competent, non-privileged session
install this release and complete a bounded task set using only the published
documentation?** It replaces the unreachable "five external developers" bar with
sessions that actually exist.

It proves:

- installation and relocation from a clean environment;
- that the documented commands are complete and truthful;
- reproducibility across at least two platforms;
- the quality of diagnostics when a step fails;
- that the bounded CLI surface works end to end without privileged knowledge.

It does **not** prove human ergonomics. Time to first working program for a
person, dot-call and interface discoverability, `mapError` tolerance and the
readability of inferred suspension stay open. No report may present the pilot as
evidence for those, and the E0 gate report must repeat the limitation.

## 2. Participants and platforms

- At least **three independent sessions**.
- At least **two platforms** among: macOS arm64, macOS x86_64, Linux x86_64.
- A session is one agent with no memory of another session: fresh checkout or
  fresh install prefix, empty cache, no reading of the compiler sources, no
  reading of previous transcripts.
- The session may read: the released artifact, its release contract, the
  user-facing docs, and this protocol. Nothing else.

Independence is part of the evidence. A session that reuses another session's
project directory, build cache or installed prefix is discarded, not averaged.

## 3. Inputs

| Input | Requirement |
|---|---|
| Release artifact | the release under test, with its SHA-256 |
| Compiler revision | recorded from `mmay version --json` |
| Canonical program | the program named in the release contract |
| Fixtures | generated by the session from the protocol, not shipped privately |

## 4. Tasks

Run in order. Record the wall-clock time for each. A step that the documentation
does not describe is a **finding**, not a workaround: record it and stop the
task.

| ID | Task | Passes when |
|---|---|---|
| T1 | Install from the artifact on a clean machine or prefix | `mmay` resolves and runs |
| T2 | `mmay version --json` and `mmay doctor` | machine-readable output, no crash, doctor reports no invented state |
| T3 | `mmay init` a new project | project files exist and are documented |
| T4 | Build and run the canonical program | documented command only, expected output |
| T5 | Typed JSON: parse one valid document, reject one invalid document | typed error with a field or index, not a panic |
| T6 | Two local packages with an import | builds, runs both engines |
| T7 | Fix one broken program from its diagnostic | the diagnostic alone is sufficient; record any missing fact |
| T8 | Concurrency slice (only when the release contains it): fan-out with timeout or cancellation, then a trace | completes, cancellation observed, traces compared |
| T9 | Relocate: move the install prefix and repeat T2-T4 | same results, no absolute-path assumptions |

## 5. Session record

Commit one file per session: `evidence/e0-pilot-<platform>-<date>.md`.

```text
Platform / OS version:
Artifact / SHA-256:
mmay version --json (verbatim):
Session start / end:
Tasks completed: T1..Tn
Failed tasks:
Undocumented steps required (finding list):
Departures from this protocol:
Time per task (table):
Verdict: pass / pass with findings / fail
```

Transcripts are kept verbatim, including failed commands. Redact personal paths
and credentials; do not redact diagnostics.

## 6. Gate thresholds

E0 closes when:

1. three sessions pass on at least two platforms;
2. **zero** tasks required an undocumented step;
3. at most one blocker per platform, and every blocker is either fixed in the
   release line or accepted by a decision that names it;
4. the gate report separates what the pilot proved from what it did not;
5. the E0 row in `roadmap.tsv` and the product roadmap carry the report link.

A pilot that fails threshold 2 is a success for the documentation and a failure
for the gate. That is the intended reading: the protocol exists to find exactly
that.

## 7. Reversal

A later human report that contradicts the pilot's findings reopens E0. The
optional human item — two written reports whenever volunteers exist — never
blocks a release and never substitutes for the pilot.
