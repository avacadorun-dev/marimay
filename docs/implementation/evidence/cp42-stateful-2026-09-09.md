`marimay-delimited` (`6471899`) and `marimay-source-lint` (`d94119e`) live in
separate local main repositories below `/workspace/Projects/Marimay/Marimay-Examples/`.
They contain Russian READMEs, ordinary Marimay parsers/models, source tests,
synthetic fixtures, unchanged process harness v1, fixed budgets, independent
oracles, findings and durable raw reports. No remote/publication is implied.
Delimited handles rectangular CSV/quoted TSV ↔ typed JSON with escaped quotes,
quoted CR/LF, Unicode/byte offsets and limits. Source-lint has six documented
text rules with nested comments/literals/interpolation, scalar columns and
stable JSON; it makes no AST/type-checker claim. Both buffer bounded inputs and
publish complete output with checked stdout or atomic file replacement.

Source tests pass 5 and 4 respectively with both engines. Process acceptance
passes 45 and 38 cases plus help, VM/native Debug/Release, three closed pipes
each, input/output boundaries, missing/denied files, symlink reads/writes,
malformed UTF-8/data and original-file preservation. In-tree snapshots retain
small deterministic language regressions, not a substitute for external acceptance.

Two shared implementation defects were fixed under existing contracts:

- D058: bytecode definite-assignment and array/enum must-analysis seed their
  queues with iterative DFS reverse postorder. No new allocations, changed
  lattice/meet/invalidation, weakened proof or larger budget. A scanner with
  674 registers/428 blocks formerly exceeded 16M verification work. The
  regression chain has 257 reverse-numbered blocks and a 10000-work cap;
  missing/conflicting proof cases remain invalid, with all allocation indices.
- D076: `substring` previously copied the whole suffix then its prefix, exhausting
  the VM string pool on 512 KiB CSV. The private primitive now lowers to
  `TEXT_TERNARY/TEXT_SUBSTRING`, opcode 164 with the existing four-register
  wire format. The selected range alone is copied by MIR/VM/native text owners.
  Public bounds/error precedence and owned results are unchanged. Hostile third
  register checks, MIR/VM/native allocation sweeps and repeated short slices of
  512 KiB cover the new path. This does not fix general VM string-pool retention.
