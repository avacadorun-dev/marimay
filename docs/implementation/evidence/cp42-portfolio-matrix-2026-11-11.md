# CP42 portfolio coverage matrix and finding dispositions

Local macOS arm64 evidence, 2026-11-11.
[Raw revisions, results and generated coverage](cp42-portfolio-matrix-2026-11-11.json).

This report closes the acceptance gap that kept CP42 open after its features
landed: the ten portfolio applications were implemented on 2026-09-09, but no
single record showed what they cover, what they prove, and what happened to each
finding they produced. CP42 itself stays `in-progress` for the startup budgets,
the bounded perf timebox, the canonical program and the release (see the
checkpoint ledger); this document is the coverage half.

The P1 reproducer, verbatim, still fails at this revision:

fn classify(value: byte): int {
  return match value {

error[I0001]: compiler does not implement accepted NAME_EXPRESSION construct

The same function with `value: int` compiles and runs, so the gap is specific to
`byte`-typed scrutinees rather than to literal-arm matching.

## What this matrix does not prove

- **One host only.** macOS 27.0.1 arm64, Debug compiler. No Linux, no Windows, no
  x86_64, no release build, no sanitizer or LeakSanitizer pass.
- **Application contracts, not language conformance.** A passing harness proves
  these ten programs behave as their own documentation says; it is not a
  conformance suite for the language.
- **One revision.** Revisions are pinned above. A later compiler change needs a
  re-run, and this report says nothing about that revision.
- **Coverage is syntactic.** A construct counted here is present in source, not
  proven exercised by every path that mentions it.
- **No Tier 1, CP41, CP39, CP40, N0 or parity claim.** Those remain the gates
  they were; N0 is excluded from CLI0 by D123, not closed.

## Regeneration

repository for the pattern list in the JSON sidecar; rerunning the scan at a new
pair of revisions is the intended way to refresh it. The sidecar also holds the
per-application case counts, wall times and the unresolved list.
