# CP42: void-ветки match и очистка выбранной ветки

Локальная проверка 2026-09-07, macOS arm64 / Apple M2 / AppleClang 21.
База языка `82e3513a591bdd19c07604b842ded8b801a1a720` с предыдущими рабочими
D089–D091 и этим D092. Это закрытие E01 внешнего config-приложения на данном
хосте, не закрытие CP42, CLI0 или матрицы Tier 1.
[Сырые результаты и хеши](cp42-void-match-2026-09-07.json).

## Воспроизведение и изменение

`match json.skipValue(decoder) { Ok(_) => {}, Err(error) => { return
Err(json.atField(error, name)); }, };` ранее давал `T0016`. В приложении
приходилось писать `const _ = match ... { Ok(_) => true, ... };`.
Старая реализация соответствовала прежнему требованию D067 о хвосте каждой
продолжающейся block-ветки. [D092](../../design/decisions.md#d092-void-block-arms-and-lexical-match-cleanup)
явно меняет это требование: пустая или продолжающаяся ветка без хвостового
выражения имеет `void`. Все недивергирующие ветки по-прежнему одного типа;
неявный `void` не подставляет значение в контексте `int` и не теряет Result.

Проверка выявила два связанных дефекта старого lowering: `defer` внутри
обычной ветки с явным хвостом завершал `check` и `run` кодом 70 без диагностики;
именованная переменная с `void` проходила `check`, но ломалась при `run`.
Общий владелец `checker_match_lower.c` теперь сохраняет результат до очистки,
исполняет LIFO-очистку выбранной ветки и восстанавливает список регистраций
после каждого пути. Возврат, `?`, `break` и `continue` сохраняют свою прежнюю
очистку без повторения на join. `checker_statement.c` отвергает именованный
`void` с `T0002` до публикации некорректного MIR; явный discard допустим.
Backend-обходов и новой грамматики нет.

## Приёмка

- Focused checker: bool/int/string/enum/tuple/record-ветки, смешение типов,
  Result discard, именованные void-переменные, MIR verifier/oracle, все
  достижимые индексы отказа checker-аллокаций. После teardown оба live-счётчика
  равны нулю, включая отрицательные случаи.
- Пять публичных тестов выполняются в VM/native. Проверены LIFO, соседние
  и внешние defer, return/propagation/loop transfer и возвращаемый массив
  через выделяющую память очистку. Одинаковый бюджет 65 536 байт меньше
  суммарного объёма временных массивов. Дополнительно исполняется `main`
  в VM, Debug native и Release native; отрицательные программы одинаково
  отвергаются `check`/`run`/`build`, без выходного исполняемого файла.
- Fixture formatter проходит точное сравнение, повторное форматирование
  и parser/AST round trip. Focused frontend/checker/public прошли в Release,
  Debug и ASan+UBSan.
- Полный `ctest --preset release` исполнил 70 проверок: 69 прошли сразу,
  source packaging обнаружил отсутствие новых untracked-файлов в Git-списке
  архива. Новые файлы работы зарегистрированы через `git add --intent-to-add`;
  контент не закоммичен. Повторный Release packaging прошёл, включая автономную
  конфигурацию исходного архива и воспроизводимость упаковки. Тест без
  `--preset release` не выбирает этот configuration-specific owner; один
  такой вызов с `No tests were found` не считается проверкой.
  Проверка ссылок затем выявила пропуск переданного пользователем handoff,
  на который уже ссылался ROADMAP. Он также зарегистрирован без изменения
  содержимого; повторные упаковка и проверка ссылок прошли. Все девять
  architecture/roadmap/memory/spec/generated/syntax/example/release/link gates
  в итоге прошли, первоначальные результаты сохранены в JSON.
- Linux amd64: frontend/checker и тот же публичный driver прошли с
  ASan+UBSan+LSan, Ubuntu 24.04 / Clang 18.1.3. Использован существующий
  контейнер под эмуляцией на M2, без сети; это диагностическая регрессия,
  не нативная Tier 1 площадка и не CI отправленной ревизии.

Обычный `/opt/homebrew/bin/mmay` и `doctor --json` подтверждают согласованные
compiler/runtime/std. SHA-256 проверенного компилятора:
`0c80a9ac3ef0dcb3827ea8f545c401dfe1e9023f9621be876e23feb4151194a5`.

## Настоящее приложение

В `/workspace/Projects/Marimay/Marimay-Examples/marimay-config` удалены
пять фиктивных bool/discard-конструкций: чтение версии, проверка выходного пути,
вывод справки, запись результата и helper проверки ошибочного конфига.
Реальные bool-результаты flush/report сохранены. `fmt --check`, `check`,
семь тестов в обоих движках и 32 процессных сценария × VM/Debug native/Release
native прошли, включая атомарность, capability denial и broken pipe.
Последний процессный прогон занял 53,36 с под другой тестовой нагрузкой;
это время проверки корректности, не latency baseline. Приложение остаётся
без коммита/remote; его проверенные source hashes приведены в JSON.

Идеи книги Владимирова в этом исправлении не применялись: основание —
воспроизводитель приложения и контракт D041/D067. Книжные страницы этому
изменению не приписываются. E02 и следующие замечания, платформенная приёмка,
ресурсы и оставшийся портфель продолжаются отдельно.
