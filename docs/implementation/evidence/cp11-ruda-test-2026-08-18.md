## Delivered surface

- `ruda test [target]` checks every test target in the module graph and
  discovers only checked `@test fn(): void` symbols from `*_test.ruda`.
  Package tests retain private access; module-root `tests/` packages see only
  public imports.
- Reports are sorted by package, canonical path, declaration span, and symbol.
  Every VM test receives a new verified bytecode execution/heap/capture state;
  every native test runs in a fresh generated executable process.
- VM is the default. `--engine native` and `--engine both` reuse canonical
  typed MIR. The `both` owner records VM termination/stdout/stderr, replays the
  same symbol natively under the same D046 grant, and compares exit, signal,
  stdout, and panic/stderr exactly. `B0007`/exit 5 is reserved for a mismatch.
- The runtime-owned test-output stack captures counted bytes, including NUL and
  LF, without publishing them to host stdout. Compiler-known
  `expect.output(string, fn(): void)` lowers through verified MIR and bytecode
  operations to the same runtime helper in VM and generated C17. A mismatch is
  deterministic bounded `G4004`; lexical D041 cleanup finishes before compare.
- The platform process owner can now capture stdout and stderr independently
  on POSIX and Windows. Both buffers are bounded and all handles/descriptors,
  child processes, and owned bytes are cleaned on every failure path.
- Exit 0 means all tests passed; matching panics and expectations are reported
  as test failures/exit 1; usage is exit 2; engine divergence is exit 5; and
  compiler/runtime pipeline failures are exit 70. Missing native toolchains
  and unsupported hosts retain the D050 public build diagnostic classes.
- Filters, watch mode, and cache controls are not silently accepted:
  `--filter`, `--exact`, `--watch`, and `--no-cache` return `U0005`/exit 2.

failure sweeps at their ownership boundaries: test-output capture and split

teardown. The higher-level CLI loop composes only those owners and the already
swept compiler/native-build owners.

## Scope boundary and residual risk

- I6 task scheduling, deterministic clock/random/temp-filesystem facilities,
  task/capability event traces, timeouts, and concurrent isolates do not exist
  yet. D051 fixes the record for the available deterministic core so later
  event fields can extend it without weakening exact termination/output bytes.
- The checkpoint intentionally does not implement the I8 filter, exact-name,
  list, shuffle, repeat, watch, cache, JSON event, doc-test, property, or fuzz
  surfaces. Named filter/watch/cache options fail closed rather than appearing
  to work.
- Local native evidence uses Apple Clang on macOS. Registered CI remains the
  owner for GNU GCC, upstream Clang, Linux LSan, and Windows/MSVC execution;
  those platform claims are not promoted from local evidence.
