# I0 iteration 1 evidence — 2026-08-10

Gate: I0 — repository and C17 bootstrap foundation.  
Iteration status: complete; gate status remains `in-progress`.  
Environment: macOS Darwin 25.3.0 arm64, AppleClang 17.0.0, CMake 4.4.2.  
Applicable decisions/contracts: D001, D021, diagnostics §§1–4, toolchain §§1–2, implementation brief §§5–6.

## Delivered vertical slice

- CMake 3.25+ C17 project, warning policy, Debug/Release presets, and ASan+UBSan preset;
- a no-network build graph with no downloaded or runtime-generated dependency;
- central checked size arithmetic, allocator ownership API, deterministic allocation failure injection, and live-allocation accounting;
- a strict bounded UTF-8 scalar decoder/validator covering overlong encodings, surrogate encodings, out-of-range scalars, and truncation;
- failure-aware writer abstraction used by the executable and tests;
- `RudaSession` as the initial owner of mutable compiler state;
- D021 resolution for diagnostics with no honest source owner;
- stable human, short, and newline-delimited JSON invocation diagnostics with invalid-UTF-8 repair and command argument context;
- `ruda version`, `ruda version --json`, top-level help, `ruda help <command>`, spelling suggestions, global diagnostic/color option validation, and stable exit status `2` for invalid invocation;
- committed diagnostic registry source/generated C/generated documentation with a stale-output check;
- C unit harness and snapshot fixtures for help, version JSON, and diagnostic renderings.

The implementation does not claim source parsing, formatting, checking, VM execution, or native Ruda compilation.

## Test surfaces

- allocation success, zero size, checked add/multiply overflow, fail-first, fail-resize, retained old allocation, resize accounting, and cleanup;
- strict one- through four-byte UTF-8, overlong encoding, surrogate, scalar above U+10FFFF, truncation, and first-invalid offset;
- exact human/short/JSON diagnostic snapshots, JSON escaping, invalid-UTF-8 replacement, nullable primary, optional command context, and writer failure;
- exact top-level help and version JSON snapshots, unknown command/option suggestions, planned-command diagnostics, task help, output failure, and diagnostic-output failure.

VM/native differential, formatter, parser, fuzzer, and Ruda-program performance evidence are not applicable to this I0 slice because no source program reaches MIR or either engine. No performance budget moved.

## Known risks and next slice

I0 is not verified. GCC, MSVC, Linux, and Windows have not run this code; Tier 1 CI is not present. Arenas, vectors, maps, owned strings, hashing, paths, process adapters, source snapshots/line indices, real file-I/O fault injection, Unicode data provenance, and the complete fixture harness remain open.

The next highest-risk slice is the source manager over owned strings/vectors/arenas: exact bytes, CRLF-aware line indices, strict UTF-8 diagnostics, stable snapshot IDs, overlays, checked growth, and allocation failure at every allocation index. That slice will establish the ownership and input-boundary patterns used by the lexer and formatter.
