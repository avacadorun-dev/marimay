# CP42: исходные позиции в отчётах падающих тестов

D095, 2026-09-07, локальный macOS arm64 / Apple M2 / AppleClang 21.
База `82e3513a591bdd19c07604b842ded8b801a1a720` с рабочими D089–D094.
[Снимок исходников, воспроизводители и результаты](cp42-test-locations-2026-09-07.json).
CP42, CLI0, полная Tier 1 матрица и remote CI остаются открытыми.

## Два воспроизведённых дефекта

D093 позволил `expect` в обычных test helpers, но CLI оставлял от panic только
код и сообщение. E09: человеку не показывались файл/строка помощника, хотя
движки сохраняли symbol/span. Во второй воспроизводимой ситуации helper
писал в stderr перед провалом ожидания. VM заменяла захваченный stderr строкой
panic; native сохранял оба фрагмента. В результате старый `--engine both`
ошибочно выдавал B0007/exit 5 при одинаковом исполнении.

Фиксированный baseline D094:
`eee144223830b3b7d3de21cd268d4f74cd2b181288c16ee8978dccaf0e3f439a`.
Один и тот же пакет с int/string generic helpers: baseline vm/native по
отдельности exit 1, both exit 5; кандидат во всех трёх режимах exit 1 с
одинаковыми полными отчётами. Это ожидаемое падение двух тестов, не успех
ожиданий. Следующий успешный тест выполняется независимо.

## Передача метаданных

[D095](../../design/decisions.md#d095-defining-source-ranges-in-test-panic-reports)
определяет строку `  --> path:line:column-endLine:endColumn` для полного
полуоткрытого диапазона panic. D022 задаёт Unicode-scalar координаты, включая
BOM и CRLF. Диапазон принадлежит определяющему helper, в том числе после
специализации; текущий файл теста не подставляется вместо источника ошибки.

`cli_test_locations.c` строит из checked facts и MIR spans каноническую
таблицу symbol/start/end → path/координаты, удаляя повторения. Пути заимствуются
у тех же неизменяемых snapshots. VM использует её при выводе. Native получает
только уже вычисленные позиции через узкую metadata API;
`c_emitter_locations.c` проверяет таблицу и встраивает её в C17. Поиск по ней
не выделяет runtime-память, не открывает исходники и не выводит source types.
Путь встраивается один раз на символ. Некорректные, повторные и неупорядоченные
metadata rows не публикуются. Native-вызовы без этой metadata сохраняют свой
прежний формат сообщения; обычный build пока не добавляет этот диапазон.

`cli_test_program.c` сохраняет stderr до panic и дописывает диагностические
байты перед сравнением движков. Первичная позиция теперь участвует в exact
comparison. Полная человеческая печать stack/suppressed-panic ещё не реализована;
низкоуровневые metadata и их прежняя проверка сохранены.

## Проверки

- Source fixture с BOM, CRLF, Unicode перед ожиданием и generic int helper
  проверяет точный диапазон `3:23-3:49`, canonical lookup и отказы writer.
  Все достижимые allocation-failure indices пройдены для подготовки таблицы,
  ошибочного source snapshot, успешной эмиссии и 16 семейств неверных native
  metadata. После полного teardown оба счётчика живой памяти равны нулю.
- Native C17 диагностирует виртуальный source path, которого нет на диске,
  с точным stderr/exit при O0 и O2. Runtime не нуждается в исходном файле.
- Публичный process driver: два generic вызова из другого файла, Unicode и
  пробелы в путях, stderr до panic, полный диапазон `5:23-5:49`, следующий
  независимый успешный тест. VM/native/both дают один и тот же полный отчёт;
  SHA-256 подтверждает сохранность исходных BOM/CRLF байтов.
- Focused Release **3/3**, 5,98 с; Debug **3/3**, 17,46 с;
  ASan+UBSan **3/3**, 25,37 с. Полный Release **73/73**, 261,20 с,
  включая source packaging. Это результаты текущего локального кандидата.
- Linux Ubuntu 24.04 amd64 / Clang 18.1.3: CLI-test **1/1**, 89,41 с, и
  публичный driver прошли с ASan+UBSan+LSan. Существующий контейнер без сети,
  M2-эмуляция; не нативная Tier 1 площадка и не remote CI.
- Все девять repository gates прошли. Повторная source packaging после
  регистрации отчёта — **1/1**, 6,88 с; `git diff --check` чистый.

Промежуточные отказы сохранены: старый точный snapshot ещё не содержал новую
позицию; новая fixture сначала имела некавыченный manifest; CMake READ
нормализовал BOM/CRLF при сравнении строки, поэтому проверка неизменности
заменена побайтным SHA-256. Они не считаются успешной верификацией.

## Цена метаданных

Парное сравнение D094/D095 на неизменных семи тестах `marimay-config`, один
и тот же временный module path, exact output, без наших параллельных сборок
или тестов. После первого создания каждого native-артефакта — три прогрева
и 11 измеренных раундов, чередующийся порядок, все samples сохранены.

| Показатель | D094 | D095 |
|---|---:|---:|
| Первое создание native test artifact, один диагностический запуск | 2,015 с | 2,192 с |
| Повторный `test --engine both`, медиана 11 | 0,538 с | 0,553 с |
| MAD / IQR повторов | 0,0010 / 0,0022 с | 0,0025 / 0,0044 с |
| Generated C | 4 074 206 байт | 4 711 790 байт |
| Native test executable | 1 404 672 байт | 1 780 768 байт |

Цена полезной диагностики измерима: около 15 мс (+2,8%) на повторный цикл,
плюс 637 584 байта C и 376 096 байт тестового executable. Первое создание
артефакта измерено один раз на вариант и не является статистической оценкой
cold startup. Эта дополнительная metadata нужна только native test output;
обычные application builds таблицу не получают. Бюджет тестового цикла 10 с
сохранён. Хост интерактивный, батарея 54%; это локальная диагностика, а не
выделенная performance acceptance площадка. Runtime-путь печати метаданных
не выделяет память, но compiler metadata и рост артефакта не объявляются бесплатными.

Compiler SHA-256:
`2b05ca481917fcf1bf08401a1937e365eab77e602ac07a499f41150db3fa796a`.
`marimay-config`: installed doctor, fmt/check, семь исходных тестов в обоих
движках и 32 процессных случая × 3 движка/профиля прошли; 61,31 с под нагрузкой,
не latency baseline. Прикладной код ради нового отчёта менять не пришлось.

Идеи книги Владимирова в D095 не применялись. Основание — E09, сохранённые
panic metadata и воспроизведённая потеря stderr; книжные страницы не приписываются.


## Повтор прикладных нагрузок на итоговом кандидате

Неизменённые входы `marimay-config`: маленький VM — первый 0,283 с,
семь повторов 0,275–0,289 с; JSON 1 048 459 байт — VM 3,569 с с version
сначала и 5,051 с с version в конце, native 0,250/0,331 с. Семь тестов
в обоих движках — 0,5857/0,5713/0,5733 с. Пиковый RSS — 155 746 304 байта
VM и 94 683 136 байт native при бюджете 256 МиБ. Все результаты проверены.

Первый запуск свежего native-файла — **0,524 с при бюджете 0,1 с**;
последующие — 0,0038–0,0059 с. Этот дефект остаётся открытым. Большие входы
измерены по одному разу: это локальная диагностика совокупного кандидата
D089–D095, не устойчивая Tier 1 приёмка и не доказательство, что ускорение
JSON вызвано D095. Полный сырой отчёт с условиями, входами и хешами вложен
в парный JSON. Приёмка приложения и CLI-альфы не закрыта.
