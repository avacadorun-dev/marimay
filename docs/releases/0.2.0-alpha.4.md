## Reference slice

The reference slice for this alpha is the `marimay-notes` application at
revision `c5ec692f3829b4c80facc8864202ae136be3173f` (tree
`8a46ffe1a4a49c6eb41cc51d6fafd6c96d369c15`, content digest
`sha256:7bb57548a2f40451e601878102526af074b234266fe6828957d4695b39e2634d`).
It is built from a fresh checkout of
<https://github.com/marimay-lang/marimay-notes> by the compiler built from the
tagged revision, using only the commands its README documents. The CI job
`reference-slice` enforces the same claim on every change.

The program is a local notes CLI: seven source files, 958 lines across three
packages, exercising module imports, record declarations, typed `Option` and
`Result`, postfix `?`, contextual `mapError`, `match`, string interpolation,
managed arrays, insertion-ordered sets, iterating `for`, declared tests,
capability-gated `std/fs`, UTF-8 byte conversion and a public function surface
over eight `std/*` packages. It does not exercise enums, interfaces, generic
declarations, maps, `while`, `defer`, `unsafe`, `extern`, mutable bindings or
`as` casts, and the release makes no claim about those families.

[The reference-slice contract](../implementation/reference-slice.md) defines the
pin, the derivation and the update procedure.

## Measurement redefinition

The CP42 startup budgets of 2026-09-09 included a native `first execution` row
with a 100 ms ceiling. Re-measurement on 2026-11-11 showed that the row measured
the platform, not the compiler: a trivial `int main(void) { return 0; }` binary
also costs about 240 ms on first execution on the same host, because the fresh
Mach-O image is paged in and verified before `main`. Decision D125 therefore
redefines the accepted number as the repeated native execution time, with the
100 ms ceiling, and requires the first-execution figure to be published next to
the same-host trivial baseline. Application runs are measured against that
baseline, not against zero. Evidence:
`docs/implementation/evidence/cp42-startup-budget-recheck-2026-11-11.md`.

The re-measured rows on 2026-11-11 pass with the redefinition in place: the
small VM row runs in 154–226 ms against its 500 ms ceiling, and the warm
`test --engine both` row in 0.44–1.86 s against 2 s.

## Changes since 0.1.0-alpha.3

This slot adds acceptance evidence, not language surface. No source syntax, no
VM/native semantics, no standard-library inventory and no wire contract changed;
the added commands, packages and tests listed below were already in
`0.1.0-alpha.3` unless a line says otherwise.

- **Portfolio coverage and dispositions** (#24). One matrix records the ten
  external CLI applications against the constructs they exercise, the engine,
  the acceptance command and the recorded result at compiler `9139cca`: 51 source
  tests and 312 process cases, every `check` clean, every test passing on both
  engines, every process harness green. Each of the seventeen findings the
  portfolio produced now carries a disposition — fixed, accepted debt, accepted
  as designed, or carried by another issue — including the reproduced
  byte-literal `match` gap (`I0001`), rune and collection-key equality, compound
  `for` recovery, the VM string-retention defect, and the source-lint `I0001`.
  Evidence:
  [coverage matrix and finding dispositions](../implementation/evidence/cp42-portfolio-matrix-2026-11-11.md).
- **Startup budgets re-measured** (#25). The two autostart-shaped rows pass; the
  native `first execution` row is re-budgeted by D125 as described above rather
  than repaired, because its 240 ms belongs to page-in and code-signing
  validation of a fresh Mach-O image on this host, not to Marimay, whose own
  startup is 5–11 ms. Evidence:
  [startup budget re-check](../implementation/evidence/cp42-startup-budget-recheck-2026-11-11.md).
- **The reference slice is pinned and enforced** (#27). `marimay-notes` is
  pinned at `c5ec692` with its tree and content digest, its construct profile is
  derived from source by `tools/check-reference-slice`, and the new
  `reference-slice` CI job builds it from a fresh public checkout with the
  compiler from the same revision. The first pushed-revision run passed in 84 s
  with 36 process cases and 21 closed-pipe checks. Evidence:
  [reference slice](../implementation/evidence/cp42-reference-slice-2026-11-11.md).
- **One bounded performance timebox, closed with three exits** (#26, D127). The
  four worst rows were worked under a four-week timebox with an unchanged
  corpus, fresh processes, alternating samples and paired A/B plus A/A controls.
  `word-frequency` fell from 130.70 ms to 85.73 ms (−34.4%, 6.68x to about 4.3x
  its Go column) through three mechanisms: [one separator search per
  split](../implementation/evidence/cp42-split-separator-search-2026-11-11.md),
  [one allocation per enumerated
  value](../implementation/evidence/cp42-enum-single-allocation-2026-11-11.md),
  and [one validation, one resolution and a surviving memo per string-keyed map
  lookup](../implementation/evidence/cp42-string-key-lookup-2026-11-11.md) plus
  [its
  memo](../implementation/evidence/cp42-string-key-lookup-memo-2026-11-11.md).
  `rune-frequency` fell from 23.03 ms to 20.74 ms (−9.94%, about 3.1x Go) when
  [a rune array element became a dense scalar in the native
  emitter](../implementation/evidence/cp42-rune-dense-scalar-2026-11-13.md).
  `frequency-map` and `unique-set` exit as
  [accepted debt](../implementation/evidence/cp42-collection-rows-debt-2026-11-13.md):
  an `int`-keyed get+put pair measures 23.9 ns and a `Set<int>` insertion
  16.4 ns, spread across resolution, validation, hashing, the probe and status
  plumbing with no frame above a fifth of the time, and an isolated C
  replication of the same two calls measures 25.8 ns per pair, so the generated
  code is not the gap. A fused collection update at an estimated 8–10 ns per
  pair is named as the next hypothesis with its own decision and is not part of
  this alpha. Four candidate mechanisms were measured and rejected, each with
  its record: [a pool of released object
  blocks](../implementation/evidence/cp42-released-object-pool-2026-11-11.md)
  (nothing to collect on these rows), the inline short-key comparison and the
  earlier shared-storage and string-publication families in the same evidence
  series. Nothing further enters the alpha line without a new decision, and
  `word-frequency` stays above its 2.0x Go target under issue #3.
- **Repository process** (#43, #44). The publication guard's author-line
  exception is closed at six historical squash-merge objects (D126) and API
  squash merges are no longer used for accepted work, so the exception cannot
  grow with each delivery.

## Scope and compatibility

Source language, VM/native semantics, bounded standard library and all wire
contracts are unchanged from [`0.1.0-alpha.3`](0.1.0-alpha.3.md). The measured
`0.1-design` language surface, the available and staged command inventory, and
every compatibility statement are unchanged; this slot adds no command. The
reference slice names what builds today; it is not a compatibility promise for
other programs.
